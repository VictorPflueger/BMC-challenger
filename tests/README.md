# Tests

The tool needs none of this: it is static files. The tests run on Node.js 22 without dependencies; the browser suites also need Playwright with Chromium, the suites that run Vici's own checks (`vici`, `storage`, `live-dialog`, `report`) a checkout of ViciDesign next to the repository (`../ViciDesign`, or the folder in `VICI_DIR`), and the suites that hand the file to the Prototype Ideator's own reader (`handoff`, `report`) a checkout of the Ideator (`../PrototypeIdeator`, or the folder in `IDEATOR_DIR`). No test calls the real API or spends money: every request that leaves the local server is refused, and a stand-in answers for the API (`lib/standin.mjs`, below).

## What runs

`node tests/run-all.mjs` runs every suite in order and, when all thirty-six pass, ends with `ALL SUITES PASSED (36 of 36)`. `node tests/run-all.mjs unit shell` runs only the named ones, and `--require-vici` fails a suite that needs a ViciDesign checkout instead of skipping its Vici checks, as GitHub Actions does; on GitHub Actions the Ideator's reader is required too. Each suite can also run on its own and prints its own success line, such as `ENGINE OK`.

## Setup for the browser suites

```
npm install -g playwright@1.56.0
npx playwright install chromium
git clone https://github.com/VictorPflueger/ViciDesign ../ViciDesign
NODE_PATH="$(npm root -g)" node tests/run-all.mjs
```

`PLAYWRIGHT_MODULE` points the suites at a Playwright folder, `CHROME_PATH` at another Chromium or Chrome, and `BMC_TEST_OUT` at the folder for screenshots (by default `bmc-challenger-tests` in the system's temporary folder). The parity suite looks for the siblings next to the repository (`../SWOT-challenger`, `../PESTEL-challenger`, `../PrototypeIdeator`) or in the folder `SIBLINGS_DIR` names; `handoff` and `report` take the Ideator from `IDEATOR_DIR` or `../PrototypeIdeator`.

## The stand-in for the API

`lib/standin.mjs` answers `https://api.anthropic.com/**` inside a Chromium context, as the real API would answer a browser: the CORS headers, GET `/v1/models`, and each agent's answer as a stream of server-sent events with its usage. By default it plays the recorded answers of Tidewell Lines, in English or German; a suite's script can answer any request with an error, hold it until Abort, cut the connection, pause a search turn, report other usage or answer with a planted defect. It never reaches the network, and its key is a fake one only the tests use.

## The private term list

`tests/hygiene.mjs` checks every published file against a private list of terms that must never appear in this public repository. The list never enters the repository. It is read from the `HYGIENE_TERMS` environment variable (a repository secret in CI), from the file `HYGIENE_TERMS_FILE` names, or from `../.hygiene-terms` next to the repository folder; one entry per line, "term<TAB>what it is". Without a list only the generic checks run and the suite says so: `HYGIENE GENERIC OK` instead of `HYGIENE OK`. The repository has no `HYGIENE_TERMS` secret yet, so CI runs the generic checks and each push runs the full check locally first.

## The golden cases

`fixtures/golden.json` holds the plan's golden cases B0 to B2 and the boundary cases as JSON (PLAN.md §5): the bands, the expected values, the block states and every display string in English and German. `engine` recomputes them. `fixtures/handoff-example.json` is the brief's example of the handoff file (4.3), which `schemas` validates.
